# Append-Only Memory Protocol

一套面向长期陪伴型 AI 应用的追加式纯文本记忆协议方案。

核心理念：**记忆只追加、不覆盖；分层检索、按需加载；稳定前端兜底，动态内存不堆积。**
目标是在本地大模型或 DSH 生态中的陪伴类应用，在多轮会话、长时间跨度下能保持人格一致、记忆连续、成本可控，并且可以跨模型迁移。

## 为什么需要它

本地模型和多数陪伴类应用本身没有持久记忆。常见做法是把历史对话不断塞进上下文，但会带来三个问题：

- **缺失了全景感：** 历史跨度越多，模型越容易理解自己，而不是遵守初始设定。
- **越聊越贵：** 上下文越堆越厚，输出 token 越贵，长期运行成本不可控。
- **换模型会丢档：** 记忆如果散落在聊天记录里，更换模型或客户端后很难迁移。

## 与现有项目的关系

本方案不是替代 Mem0、Supermemory、DSH 记忆插件或向量数据库，而是一套面向本地、单人、长期陪伴场景的轻量级记忆协议。它不依赖云端服务，也不绑定特定模型，重点从输入格式一致、记忆可迁移和成本可预期出发。

和现有项目的主要区别：

- **Mem0 / Supermemory / memU：** 偏“云端服务 + 向量检索”；本方案更“本地纯文本 + 追加式档案 + 缓存成本低”。
- **DSH 原生记忆机制：** 依赖官方消息日志、Agent.md、技能文件；本方案更像一套独立协议，不依赖 DSH 内部实现。
- **DSH 记忆插件 (dsh-memory, dsh-memex 等)：** 多用 SQLite、工具调用、自动召回；本方案更偏“追加式、纯文本、可迁移、可手动运行”。
- **本地 Git/Wiki 记忆 (ai-memory, OpenHuman 等)：** 也强调本地文件和版本管理；本方案更聚焦“陪伴型 AI 的长单人设、带代际更新、验证闭环”。

## 核心机制

### 1. 追加式纯文本档案

记忆只追加，不覆盖。所有内容用极简电报体记录，保留关键情境、画面、结论，但不逐字保存完整对话。这样既能积累长期档案，又不会让上下文被大量历史对话污染。

### 2. 分层检索通道

记忆分为三层：

| 层级 | 作用 | 最高常驻 |
| :--- | :--- | :--- |
| 世代档案 | 记录长期形成的稳定印象 | 常驻 |
| 当前模块 | 编号 + 情绪值 + 短句子 | 常驻 |
| 单条正文 | 具体回忆细节 | 按需加载 |

这样历史记忆只挑最相关的，也不会一次性把大量内容塞进上下文。

### 3. 稳定前缀 + 动态注入

输入顺序固定为：
`人格卡 → 约定与边界 → 世代摘要 → 目录 → 按商条目 → 用户输入`

稳定部分放在最前面，利于缓存命中；动态部分放在后面，只在需要时注入。

### 4. 输出闸门

记忆写入遵循三条规则：

- 每日最多新增少量条目；
- 使用电报体，不写长句；
- 不暴露内部数值，如编号、状态标签、余弦值等。

这能防止框架越写越厚，也能避免模型把内部机制对出口。
