# AOMP 架构说明

## 整体数据流
用户输入 -> 取活跃目录 -> 按需加载正文 -> 拼装固定顺序提示词
-> 调用大模型 -> 人格自整 -> 经输出闸门决定是否追加记忆

## 三层检索结构
1. 世代摘要：常驻、极短，记录长期稳定印象（存在 persona.json 的 generation_summary）
2. 当前目录：常驻，只放「编号 + 情绪词 + 短钩子」，省 token
3. 单条正文：按需加载，被翻起时 strength 回升

## 输入固定顺序
人格卡 -> 约定与边界 -> 世代摘要 -> 目录 -> 按需条目 -> 用户输入
（稳定部分在前利于缓存，动态部分在后只在需要时注入）

## 输出闸门三条规则
- 每日最多新增少量条目（daily_write_cap）
- 用最短电报体，不写长段、不存完整对话
- 不向用户暴露内部数值（编号 / strength / 情绪标签 / 亲密值）

## 记忆衰减
FuzzyMemory：strength 随时间指数衰减，被检索时微量回升，
低于阈值(0.1)不再进入目录，但原文始终保留（追加式，不删除）。
